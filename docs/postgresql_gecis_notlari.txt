1.3 SAVRONIK CEVABI (2026-07-28) — YENI SAYFA/UC KAYIT YORDAMI  [S1 + S2 kapandi]
    Yeni bir endpoint'e sahip sayfa olusturuldugunda veritabaninda YALNIZCA su
    3 tabloya satir eklenir; BASKA TABLOYA EKLEME GEREKMEZ:
      1) webpage                    -> sayfanin adi.  Or: WorkPlan  (webpage id 37)
      2) roleright                  -> (webpage_id, ability_id).  Or: 37 | 5
         (ability_id 5 = "Hepsi" yetenegi; yetenek listesi page_abilities tablosunda)
      3) roleright_endpoint_mapping -> (roleright_id, endpoint).  Or: 156 | "workPlan/"
         (156 = az once eklenen roleright kaydinin id'si, "workPlan/" = controller
          sinifindaki endpoint uzantisi)

    ENDPOINT YAZIM BICIMI — GERCEK HOST SATIRLARI (2026-07-29, dump):
      86 | 30 | /system/access-group/get/**
      82 | 29 | /system/access-group/post
    Ilk turdaki "workPlan/" ornegi SADELESTIRILMISTIR; gercek konvansiyon sudur:
      - Yol BASINDA '/' vardir ve "api/" oneki YOKTUR ("/system/..." ile baslar).
      - Joker '**' ile yazilir (Ant/Spring yol kalibi gorunumu), '/' ile bitirme
        degil. '**' = altindaki tum segmentler.
      - Jokersiz satir (".../post") TAM ESLESME gibi durur.
      - !!! EYLEM ADI YOLUN ICINDEDIR: ".../get/**" ve ".../post" AYRI satirlardir
        ve AYRI right_id'lere (30 ve 29) baglidir. Yani host, okuma ve yazmayi
        HTTP METODUYLA degil, YOLDAKI FIIL SEGMENTIYLE ayiriyor.
    SONUC: Host uygulamasi REST konvansiyonu (ayni yol + farkli metot) DEGIL,
    "fiil yolda" konvansiyonu kullaniyor. Bizim uclarimiz (GET/PUT/DELETE
    /api/anketler/{id}) bu konvansiyona UYMUYOR (bkz. 2.6).

    BUNUN IKI BUYUK SONUCU:
    (a) Izin birimi TEK UC DEGILDIR; SAYFA (+yetenek) duzeyindeki YOL ONEKIDIR.
        "14 uc icin 14 izin anahtari" fikri host modeline UYMAZ (bkz. 4.2 revizyonu).
    (b) Metot bilgisi olmadigi icin AYNI YOL uzerindeki GET/PUT/DELETE ayrimi
        host mekanizmasiyla YAPILAMAZ. Ince ayrim isteniyorsa YOLLARIN kendisi
        ayrilmalidir (bkz. 2.6).

1.4 page_abilities ICERIGI — HOST VERISI (2026-07-29, host dump'indan):
      1 read | 2 create | 3 delete | 4 update | 5 all
    (Bu satirlar UYDURMA DEGILDIR, host'tan geldi. Replikaya seed edilirken

    DIKKAT — GUCLU BIR CIKARIM (dogrulanmali, bkz. S13): yetenek isimleri

ADIM 1 — SAYFA + HAK + YOL ONEKLERI (SQL; her sayfa icin bir kez)
  Sayfa "Anket" (yonetim; izin ister):

    WITH yeni_sayfa AS (
      INSERT INTO webpage (name) VALUES ('Anket') RETURNING id
    ), yeni_hak AS (
      INSERT INTO roleright (webpage_id, ability_id)
      SELECT id, 5 FROM yeni_sayfa RETURNING id
    )
    INSERT INTO roleright_endpoint_mapping (right_id, endpoint)
    SELECT yeni_hak.id, onek
    FROM yeni_hak, (VALUES
        ('/anket/get/**'), ('/anket/post/**'), ('/anket/put/**'),
        ('/soru/get/**'),  ('/soru/post/**'),  ('/soru/put/**'),
        ('/soru/delete/**')
    ) AS onekler(onek);

  Sayfa "Anketlerim" (tum personel) — ayni kalip, iki onekle:

    WITH yeni_sayfa AS (
      INSERT INTO webpage (name) VALUES ('Anketlerim') RETURNING id
    ), yeni_hak AS (
      INSERT INTO roleright (webpage_id, ability_id)
      SELECT id, 5 FROM yeni_sayfa RETURNING id
    )
    INSERT INTO roleright_endpoint_mapping (right_id, endpoint)
    SELECT yeni_hak.id, onek
    FROM yeni_hak, (VALUES
        ('/anketlerim/get/**'), ('/anketlerim/post/**')
    ) AS onekler(onek);

ADIM 2 — YETKININ PERSONELE VERILMESI (host arayuzunden)
  Yetki ATAMASI (rolerightmapping satirlari) SQL ile ELLE YAZILMAZ: host'un
  kendi yetkilendirme ekranindan yapilir. Orada
    - "Anket" sayfasi anket yonetimi yapacak rollere (1.1'e gore aday: 3, 5, 10),
    - "Anketlerim" sayfasi TUM personel rollerine
  verilir. Boylece atamalar host'un kendi denetim/kayit akisindan gecer.
  (Gerekirse ayni sey rolerightmapping'e (role_id, right_id) INSERT'i ile de
   yapilabilir; right_id ADIM 1'de olusan hak satirindan SELECT ile bulunur,
   sabit yazilmaz.)

ADIM 3 — DOGRULAMA
  Asagidaki sorgu, bir personelin sayfayi gorup goremedigini soyler; uygulamanin
  calistirdigi sorgunun AYNISIDIR (backend/repositories/yetki_sorgulari.py):

    SELECT 1 FROM "user" u
      JOIN rolerightmapping m ON m.role_id = u.role_id
      JOIN roleright r        ON r.id = m.right_id
      JOIN webpage w          ON w.id = r.webpage_id
     WHERE u.id = :staff_id AND w.name = :sayfa_adi
     LIMIT 1;

  Beklenen: yetkili personel icin 'Anket' -> satir DONER; yetkisiz personel icin
  'Anket' -> satir YOK ama 'Anketlerim' -> satir DONER.

GERI ALMA (rollback)

  webpage satirlari silinir (FK yonu geregi tersten). Tablolar DUSURULMEZ;
  bunlar HOST'un tablolaridir.
